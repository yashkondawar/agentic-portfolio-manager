# Setting up a shared copy

You have a portable copy of the Agentic Equity Researcher. It is complete and runnable, with two
large derived/third-party directories left out on purpose (details at the bottom).

## 1. Install and verify

```bash
python -m pip install -r tools/requirements.txt
python tools/preflight.py
```

`preflight.py` is the answer to "did anything arrive broken?" — it checks that every declared
dependency imports, the sector registry is internally consistent (E1–E11, and it fails on any
`status: pending` playbook), every schema and config parses, every backticked path reference in the
markdown resolves, the two copies of `reportStyle.js` are byte-identical, and every `tools/*.py`
compiles. **Expect `7/7 checks passed`.** Run it again after any edit to `config/`, `schema/`,
`prompts/` or `tools/`.

Nothing above needs an API key. The whole default pipeline, the BSE/Screener fetch and the corpus
toolchain run key-free. Do **not** merge `tools/disclosure_fetcher/requirements.txt`'s
Gemini/Tavily block into `tools/requirements.txt` — the offline test asserts key-free mode never
imports those, and it skips its web-fallback scenarios when they are absent.

## 2. Optional: the FORMAT stage (styled `.docx`)

Only needed for step 9. `node_modules/` was excluded, so restore it:

```bash
cd tools/report_formatter && npm install && cd ../..
```

## 3. Open it in Claude Code

Open the repo root. `CLAUDE.md` is the orchestrator playbook and takes over from there — start with
its Preflight section, then the run lifecycle. `README.md` has the repo map.

To run a company: put documents in `input/<TICKER>/` per `input/README.md`'s naming convention, then
ask Claude Code to initiate coverage on that ticker.

## 4. Look at the worked example first

`workspace/NALCO/` is the only executed run and is kept **including its defects**, because several
are what the validators exist to catch. `workspace/README.md` lists them. Read that before trusting
any single number in there — notably, its citation gate reads `FAIL` with no override, so that
report does not pass verification.

```bash
python tools/validate_state.py workspace/NALCO     # expect 0 errors, a few honest warnings
```

Its `cache/` was excluded (16 MB of derived markdown). Regenerate if you want to re-run extraction:

```bash
python tools/convert_docs.py NALCO
```

That needs the source PDFs in `input/NALCO/`, which are **not** in this copy — the original 13 NALCO
PDFs were already gone from the source machine. Everything downstream of extraction
(`facts/`, `findings/`, `state/`, `report/`, `exports/`) is present, so the run is inspectable
end-to-end even without them.

## What was excluded, and why

| Excluded | Size | Why, and how to restore |
|---|---|---|
| `reference/er_corpus/pdf/` | ~375 MB | **165 third-party broker research PDFs.** Not ours to redistribute, and they dominate the archive. Regenerate with `python tools/er_corpus/fetch_corpus.py --seeds reference/er_corpus/seeds/all_pending.txt` (key-free; some broker URLs have since died — `tools/er_corpus/README.md` documents which and why). |
| `reference/er_corpus/md/` | ~25 MB | Full-text markdown conversions of those same PDFs. Same reasoning. Regenerated by the same fetch command. |
| `tools/report_formatter/node_modules/` | ~10 MB | Restore with `npm install` (see step 2). `package.json` and `package-lock.json` are included. |
| `workspace/NALCO/cache/` | ~16 MB | Derived conversion output. See step 4. |
| `__pycache__/`, `*.pyc` | — | Build artefacts. |

**What IS included from the corpus**, and why it matters: `reference/er_corpus/digest/` (all 165
compressed reading copies), `manifest.csv`, `profile.json`, `profile_summary.md`, `seeds/` and
`extracts/`. That is enough to (a) verify every provenance claim in the 32 sector playbooks, and
(b) regenerate the counted tables in `docs/ER_CORPUS_FINDINGS.md` via
`python tools/er_corpus/profile_notes.py`.

> **One judgement call to make yourself.** The digests are deterministic extracts of third-party
> broker notes — verbatim cover pages, not paraphrase. Keeping them is right for internal use, where
> they are the evidence base the sector playbooks are grounded in. If you are passing this outside
> your own team, consider dropping `reference/er_corpus/digest/` too; the playbooks then still work,
> but their provenance lines become unverifiable claims rather than checkable ones.

## Where the analysis philosophy lives

Read these two before changing anything, because they explain *why* the repo is shaped as it is:

- `docs/ER_CORPUS_FINDINGS.md` — what 165 real Indian initiation notes actually do, counted. §5 is
  the load-bearing one: 94% of ratings are positive, so the rating carries almost no information and
  the analysis carries nearly all of it. That finding is why `config.report.stance` is
  `evidence_first`.
- `docs/DESIGN_DECISIONS.md` — every deliberate design call and the defect that prompted it.
